# Комплект личного рабочего проекта

| | |
|---|---|
| **Версия** | 1.0 |
| **Дата** | 2026-09-14 |
| **Владелец** | Ипполитов Иван, директор департамента информационных технологий |
| **Статус** | рабочий документ |

Что выдаётся человеку, у которого нет ни репозитория продукта, ни задач на разработку —
менеджеру, руководителю, любому, кто работает не с кодом, — чтобы он завёл себе рабочее
пространство в Claude Code.

Смысл и польза такого проекта описаны для читателя в регламенте:
[docs/regulations/claude-code/lichnyj-proekt.md](../../../docs/regulations/claude-code/lichnyj-proekt.md).
Здесь — сам комплект и порядок его выдачи.

## Что лежит здесь

```
razvernut-lichnyj-proekt.md   стартовое сообщение агенту: разворачивает проект с нуля
settings.json                 разрешения для личного проекта
commands/pbe-issue.md         задача Трекера: прочитать, разобрать, ответить, завести
commands/pbe-wiki.md          страница Вики: прочитать, забрать себе, опубликовать
commands/pbe-draft.md         черновик письма или сообщения, письмо — в двух форматах
commands/pbe-note.md          заметка и напоминание в консоли Powbee
```

Скриптов здесь **нет намеренно**: они ведутся в [../../scripts/](../../scripts/), и вторая
копия разошлась бы с первой молча — та же причина, по которой копии в `.claude/` проектов
считаются копиями, а не форками ([основы](../../../docs/regulations/claude-code/osnovy.md),
п. 3.1).

## Как собрать комплект к выдаче

```bash
cd automation/claude/lichnyj-proekt
mkdir -p /tmp/komplekt/scripts
cp razvernut-lichnyj-proekt.md settings.json /tmp/komplekt/
cp -r commands /tmp/komplekt/
cp ../../scripts/{tracker-issue.sh,tracker-create.py,tracker-update.py,\
wiki-page.sh,wiki2md.py,wiki-push.py,md2rtf.py,check-links.py} /tmp/komplekt/scripts/
```

Дальше папка `/tmp/komplekt/` отдаётся человеку — архивом или копированием в его пустую
папку проекта. Стартовое сообщение ожидает ровно такую раскладку: `scripts/`, `commands/`,
`settings.json` рядом с собой.

## Что выдать вместе с комплектом

1. **ID организации** и **токен консоли** — персонально, через парольный менеджер.
   Токен Трекера человек получает сам на странице консоли.
2. Ссылку на [основы](../../../docs/regulations/claude-code/osnovy.md) и на
   [страницу про личный проект](../../../docs/regulations/claude-code/lichnyj-proekt.md).
3. Одну фразу голосом: запускать Claude Code надо **из папки проекта**, и первое,
   что сказать агенту, — «прочитай `razvernut-lichnyj-proekt.md` и сделай, что там написано».

## Разрешения: чем отличаются от проектных

`settings.json` здесь мягче, чем у команд разработки, и это осознанно.

- **`git push` стоит `ask`, а не `deny`.** В продуктовых репозиториях пуш запрещён:
  он уходит в общую ветку, которую видят все. Здесь репозиторий личный и приватный,
  а пуш — единственная защита от потери ноутбука; вопрос перед отправкой достаточен.
- **Три пишущих скрипта стоят `ask`.** `tracker-create.py`, `tracker-update.py`
  и `wiki-push.py` пишут в общие системы, которые читают другие люди. Сухой прогон
  и боевой запуск отличаются одним флагом в конце команды — правилом их не различить,
  поэтому спрашивается каждый запуск.
- **`curl` стоит `ask`** — им агент ходит в API консоли за заметками; заодно это
  отсекает произвольные сетевые вызовы мимо обвязки.
- **Хуков нет.** Защищать нечего: веток задач, защищённых веток и PR в личном проекте
  не бывает. Разрушительное (`rm -rf`, `git clean`, `reset --hard`) закрыто списком.

## Правки

Комплект ведётся здесь и раздаётся отсюда. Человек, у которого он развёрнут, свой
`CLAUDE.md` и свои документы правит свободно — это его рабочее место. Утилиты и команды
из комплекта — не правит: нашёл ошибку или нужна доработка — задача в очередь `CRM`,
дальше правка расходится всем, у кого комплект уже развёрнут.
