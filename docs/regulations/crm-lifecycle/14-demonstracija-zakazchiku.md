# Этап 14 — Демонстрация заказчику

> **Рабочая копия — здесь ведём и дописываем.** Регламент не финальный.
> Выгружено из Вики 2026-08-12: [powbee/reglamenty/treker-new/crm-svodnyjj-reglament/jetap-14-demonstracija-zakazchiku](https://wiki.yandex.ru/powbee/reglamenty/treker-new/crm-svodnyjj-reglament/jetap-14-demonstracija-zakazchiku).
> Первоисточник с тех пор мог измениться — сверяться перед переносом правок обратно.

## 1. Область применения

Регламент определяет порядок демонстрации клиенту выпущенного функционала и закрытия задачи. Является завершающим этапом жизненного цикла.

## 2. Ответственные и участники

| Роль | Участник | Функции |
|------|----------|---------|
| Ответственный | Менеджер клиента | Организация демонстрации, закрытие задачи |
| Участник | Клиент | Приёмка выпущенного функционала |
| Консультант | БА / Тимлид | Технические и функциональные разъяснения при необходимости |

## 3. Общие положения

После выпуска в продуктив менеджер клиента демонстрирует клиенту реализованный функционал, получает подтверждение приёмки и закрывает задачу. Это финальная точка — после закрытия задача считается завершённой.

## 4. Порядок выполнения

### 4.1. Когда задача попадает на этап

- Подзадачи «Разработка» в статусе «Демонстрация заказчику»
- Изменения успешно выведены в продуктив

### 4.2. Проведение демонстрации

Менеджер клиента организует демонстрацию выпущенного функционала клиенту. Формат — по договорённости с клиентом:
- Онлайн-встреча с показом,
- Отправка release notes с описанием изменений,
- Любой другой согласованный формат.

В рамках демонстрации:
1. Менеджер клиента показывает реализованный функционал согласно согласованной постановке.
2. Клиент проверяет соответствие результата ожиданиям.
3. Клиент подтверждает приёмку.

### 4.3. Варианты решения

**Клиент подтвердил приёмку:**
1. Менеджер клиента закрывает основную задачу (статус **«Закрыта»**).
2. Все оставшиеся открытые подзадачи закрываются.

> **Багрепорты входят в число подзадач, которые надо закрыть.** Дефекты по
> доработкам этой задачи живут подзадачами её подзадач «Разработка»
> ([этап 11](11-testirovanie-i-revju.md), 4.5.2), то есть на втором уровне дерева.
> Закрываются наравне с остальными: дефект либо выправлен, либо багрепорт закрыт
> явно, с обоснованием.

**Выявлены замечания после релиза:**
- Если замечание — **баг**: создать задачу типа «Ошибка» в очереди
  [`SUPPORTDEV`](https://tracker.yandex.ru/SUPPORTDEV). Функционал уже на проде,
  поэтому дефект идёт во внешний контур, а не в `BUGREPORTS`. Заводить его в
  `SUPPORTDEV` можно напрямую — проходить через `SUPPORT` не требуется, эта
  очередь принимает обращения клиентов по почте.
- Если замечание — **новое требование**: создать новую задачу типа «Улучшение»
  в очереди `CRM` (жизненный цикл с этапа 1).
- Текущая задача закрывается после фиксации новой.

> Замечания, возникшие после выпуска в продуктив и прохождения клиентского тестирования, **не являются основанием** для возврата исходной задачи на доработку. Они оформляются как новые задачи.

## 5. Критерии завершения

- [ ] Клиент ознакомлен с выпущенным функционалом
- [ ] Приёмка клиентом подтверждена
- [ ] Основная задача закрыта
- [ ] Все дочерние подзадачи закрыты на обоих уровнях дерева, включая багрепорты (4.3)
- [ ] При наличии замечаний — созданы новые задачи («Ошибка» / «Улучшение»)

## 6. Учёт трудозатрат

По усмотрению менеджера клиента. При необходимости — в основную задачу.
