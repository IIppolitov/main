# Этап 1 — Создание задачи

## 1. Область применения

Регламент определяет порядок создания задач на доработку CRM-системы. Обязателен для всех сотрудников, инициирующих задачи на улучшение продукта.

## 2. Ответственные и участники

| Роль | Участник | Функции |
|------|----------|---------|
| Ответственный | Менеджер клиента | Создание задачи, заполнение атрибутов, передача на валидацию |
| Участник | Клиент / внутренний заказчик | Формулировка бизнес-потребности |
| Получатель | Владелец продукта | Приём задачи на валидацию |

## 3. Общие положения

Этап является стартовой точкой жизненного цикла задачи. На этом этапе фиксируется бизнес-потребность без детализации технической реализации.

## 4. Порядок выполнения

### 4.1. Когда создаётся задача

- Клиент обращается к менеджеру клиента с запросом на доработку (через внешнюю систему, почту или напрямую).
- Внутренний сотрудник инициирует задачу по собственной инициативе.

### 4.2. Создание задачи в Трекере

1. Создать задачу в очереди CRM с типом **«Улучшение»**.
2. Заполнить обязательные атрибуты (см. таблицу ниже).
3. Назначить исполнителем **владельца продукта**.
4. Оставить статус **«Открыта»**.

### 4.3. Обязательные атрибуты

| Атрибут | Требование | Пример |
|---------|-----------|--------|
| Название | Начинается с мнемоники клиента | `SRV. Добавить экспорт отчёта в Excel` |
| Тип | Улучшение | — |
| Тег | Мнемоника клиента | `SRV` |
| Блок «Цель / Проблема» | Описывает **что** и **зачем**, не **как** | «При просмотре таблицы пользователь тратит избыточное время на...» |
| Срочность БА | Целое от 1 до 5, где **1 — самое приоритетное** | `2` |
| Приоритет | `TODO: уточнить` — нужно ли стандартное поле Трекера, раз есть «Срочность БА» | `TODO: уточнить` |

**Что такое «Срочность БА».** Поле заполняет менеджер клиента, и оно определяет **порядок,
в котором команда бизнес-анализа разбирает задачи** ([этап 3](03-biznes-analiz.md), 4.2):
очередь сортируется по срочности, внутри одного значения — по дате поступления.

Чего поле не делает:

- **не назначает срок** — это порядок в очереди, а не обязательство по дате;
- **не влияет на приоритет разработки** — очерёдность разработки определяется
  клиентским проектом и спринтом ([этапы 7](07-sbor-v-proekty.md) и [8](08-nabor-sprintov.md));
- **не работает, если у всех задач стоит 1.** Значение 1 имеет смысл, только пока
  таких задач единицы. Перекос разбирается на сборе команды БА с участием
  владелец продукта ([этап 3](03-biznes-analiz.md), 4.2).

Незаполненное поле команда БА трактует как срочность 5 — задача уходит в конец
очереди. Это не наказание, а следствие: без значения аналитику не на что опереться.

### 4.4. Рекомендуемые атрибуты

| Атрибут | Описание |
|---------|---------|
| Юзкейс | Сценарий использования от лица пользователя |
| Пример реализации | Предложение клиента (носит рекомендательный характер; команда вправе предложить альтернативу) |

### 4.5. Завершение этапа

Задача готова к передаче, когда:
- заполнены все обязательные атрибуты,
- исполнителем назначен владелец продукта,
- статус — «Открыта».

## 5. Критерии завершения

- [ ] Тип задачи — «Улучшение»
- [ ] В названии и теге присутствует мнемоника клиента
- [ ] Заполнен блок «Цель / Проблема» с описанием бизнес-потребности
- [ ] Заполнено поле «Срочность БА» (1–5)
- [ ] Исполнитель — владелец продукта
- [ ] Статус — «Открыта»

## 6. Учёт трудозатрат

По усмотрению автора задачи. При необходимости — в основную задачу.
