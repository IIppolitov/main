# Этап 5 — Оценка задачи

## 1. Область применения

Регламент определяет порядок оценки трудозатрат по задачам. Обязателен для руководителей направлений и специалистов, участвующих в оценке.

## 2. Ответственные и участники

| Роль | Участник | Функции |
|------|----------|---------|
| Координатор | Релиз-менеджер | Организация сессий, формирование очереди, заполнение таблицы оценки |
| Оценивающий (разработка) | Тимлид + команда | Оценка подзадач «Разработка», декомпозиция сложных задач |
| Участник | БА | Присутствует на всех сессиях для разъяснений; в оценке не участвует |
| Участник | QA | Присутствует на всех сессиях; даёт контекст по рискам тестирования |
| Оценивающий (дизайн) | Тимлид дизайна (опц.) | Оценка подзадач «Дизайн» |
| Получатель | КАМ | Формирование сводной оценки и согласование с клиентом |

## 3. Общие положения

На этом этапе определяется полный объём трудозатрат по задаче. Результатом является не только оценка в подзадачах, но и сводная **таблица оценки** в основной задаче, отражающая разбивку по всем фазам, включая буфер на риски.

## 4. Порядок выполнения

### 4.1. Когда задача попадает на этап

- Подзадача «Разработка» (и «Дизайн» при наличии) в статусе «Оценка задачи»
- Исполнитель — тимлид / лид дизайна

### 4.2. Сессии оценки

- **Частота:** 2 сессии в неделю для каждой команды (Администрирование и Приложение проводят **раздельные** сессии).
- **Длительность:** до 45 минут.
- **Производительность:** 7–9 задач за сессию.
- **Приоритизация:** FIFO, если иное не согласовано с Релиз-менеджером.

### 4.3. Категоризация задач для разработки

| Категория | Критерии | Порядок работы |
|----------|---------|----------------|
| Простая | Понятные требования, ограниченный объём | Сразу на оценку командой |
| Сложная | Новые модули, интеграции, архитектурные решения | Тимлид прорабатывает и декомпозирует (до 2 недель), затем командная оценка |

Декомпозиция ведётся по принципам **INVEST**: Independent, Negotiable, Valuable, Estimable, Small, Testable.

### 4.4. Работа с недостающей информацией

Если для оценки задачи нужно уточнение и это займёт более 5 минут — задача возвращается БА. Команда переходит к следующей задаче в очереди.

### 4.5. Таблица оценки в основной задаче

На сессиях команды заполняют поле **«Оценка»** (стандартное поле ЯТ) в своих подзадачах — это часы только на разработку / дизайн без буфера. После завершения всех сессий **Релиз-менеджер** берёт эти значения за основу и собирает сводную таблицу в описании основной задачи, добавляя буферные строки:

```
| Фаза         | Оценка (ч) |
|--------------|-----------|
| Разработка   |  ← сумма полей «Оценка» из подзадач «Разработка» |
| Ревью        |  ← экспертная оценка РМ                          |
| QA           |  ← экспертная оценка РМ                          |
| Риски        |  ← буфер на непредвиденное                       |
| Деплой       |  ← экспертная оценка РМ / CTO                    |
| Дизайн       |  ← поле «Оценка» подзадачи «Дизайн» (если есть)  |
| БА           |  ← поле «Оценка БА» подзадачи «Бизнес Анализ»    |
| **Итого**    |                                                   |
```

> Строки «Ревью», «Риски», «Деплой» — управленческий буфер. Разработчики их не видят и не должны ориентироваться на них: каждый видит только поле «Оценка» в своей подзадаче.

На основании строки **«Итого»** Релиз-менеджер заполняет кастомное поле **«Оценка»** основной задачи — это итоговая цифра для КАМа и клиента.

### 4.6. Завершение оценки

1. Убедиться, что в каждой подзадаче «Разработка» / «Дизайн» заполнено стандартное поле **«Оценка»**.
2. Заполнить таблицу оценки в описании основной задачи.
3. Заполнить кастомное поле **«Оценка»** основной задачи значением из строки «Итого».
4. Перевести все подзадачи в статус **«Согласование КАМ»**.
5. Назначить исполнителем подзадач — КАМ / автора основной задачи.

## 5. Критерии завершения

- [ ] Все подзадачи «Разработка» / «Дизайн» имеют заполненное стандартное поле «Оценка»
- [ ] Таблица оценки заполнена в описании основной задачи
- [ ] Кастомное поле «Оценка» основной задачи заполнено значением из строки «Итого»
- [ ] Все подзадачи в статусе «Согласование КАМ»
- [ ] Исполнитель подзадач — КАМ / автор задачи

## 6. Учёт трудозатрат

Время на проведение сессий оценки фиксируется Релиз-менеджером в основную задачу.
