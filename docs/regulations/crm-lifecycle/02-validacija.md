## 1. Область применения

Регламент определяет порядок первичной проверки задач Product Owner'ом. Обязателен для сотрудников, участвующих в оценке входящих запросов.

## 2. Ответственные и участники

| Роль | Участник | Функции |
|------|----------|---------|
| Ответственный | Product Owner | Проверка задачи, принятие решения о переходе на БА |
| Участник | КАМ / автор задачи | Предоставление уточнений при необходимости |
| Консультант | Тимлид разработки (опц.) | Первичная ориентировочная оценка по запросу ПО |

## 3. Общие положения

Этап является контрольной точкой после создания задачи. Product Owner проверяет качество постановки и соответствие задачи концепции продукта, после чего принимает решение о продвижении.

## 4. Порядок выполнения

### 4.1. Когда задача попадает на этап

- Статус основной задачи: «Открыта»
- Исполнитель: Product Owner
- Тип: «Улучшение»

### 4.2. Процедура валидации

Product Owner проверяет задачу по трём направлениям:

| Направление | Критерии |
|------------|---------|
| Качество постановки | Чётко сформулирована бизнес-проблема; цель не подменена реализацией |
| Соответствие концепции | Задача вписывается в архитектуру и продуктовую стратегию |
| Полнота информации | Достаточно данных для начала анализа |

### 4.3. Варианты решения

**Вариант А — Задача принята**

1. PO запускает скрипт, который создаёт подзадачу с типом **«Бизнес Анализ»** и назначает её на команду БА.
2. Задача передаётся на этап «Бизнес-анализ».

> Создание подзадачи БА является сигналом о том, что задача прошла валидацию.

**Вариант Б — Задача возвращена на уточнение**

1. PO добавляет комментарий с перечнем необходимых уточнений.
2. Уведомляет автора задачи.
3. Задача остаётся у автора до устранения замечаний.

**Вариант В — Задача отменена**

1. PO добавляет комментарий с обоснованием отмены (стратегические или регуляторные причины).
2. Уведомляет автора задачи.
3. Дальнейшая работа по задаче не ведётся.

### 4.4. Первичная ориентировочная оценка (опционально)

При необходимости ПО может запросить у тимлида примерную оценку трудозатрат (погрешность ±50%). Эта оценка носит исключительно информативный характер и **не заменяет** полноценную оценку на этапе 5.

### 4.5. Завершение этапа

Этап завершён, когда принято одно из трёх решений и выполнены соответствующие действия.

## 5. Критерии завершения

**Задача принята:**
- [ ] Подзадача «Бизнес Анализ» создана и назначена на команду БА

**Задача возвращена:**
- [ ] Замечания зафиксированы в комментарии
- [ ] Автор уведомлён

**Задача отменена:**
- [ ] Обоснование зафиксировано в комментарии
- [ ] Автор уведомлён

## 6. Учёт трудозатрат

По усмотрению Product Owner. При необходимости — в основную задачу.
