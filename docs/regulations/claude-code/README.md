# Claude Code в командах разработки

Четыре документа: общая база и по одному на команду. Читать в таком порядке —
основы обязательны всем, документ команды дополняет их спецификой проекта.
Пятый, [wiki.md](wiki.md), стоит особняком — он не про команду, а про инструмент,
и нужен не только разработке.

| Документ | Кому | О чём |
|---|---|---|
| [osnovy.md](osnovy.md) | всем разработчикам ИТ | доступ, VPN, установка (в т.ч. `gh`), обвязка, ядро правил, работа с гитом и данными, приёмы и анти-паттерны |
| [pbeadmin.md](pbeadmin.md) | команде админки | агенты и команды `pbeadmin`, ревью PR, гейты приёмки, технические запреты |
| [pbeapp.md](pbeapp.md) | команде приложения | агенты и конвейер `pbeapp`, ревью PR, артефакты задачи, мультибренд и сборка |
| [pbedataengineer.md](pbedataengineer.md) | отделу дата-инженеров | работа с данными и Superset: только чтение из базы, выгрузка дэшбордов в YAML, RLS как гейт |
| [wiki.md](wiki.md) | всем, кто работает с Вики через агента | доступ к API, три скрипта полными текстами, сценарии чтения и публикации, грабли, режим чата |

**[wiki.md](wiki.md) — единственный документ здесь, который отдают целиком и
без репозитория.** Тексты скриптов лежат внутри него, поэтому он работает и у
того, у кого нет ни Claude Code, ни чекаута: в разделе 8 разобран режим, где в
Вики ходит человек, а агент только читает, пишет и диктует команды. Отсюда и
исключение из правила «в регламентах не упоминаем скрипты»: здесь скрипты и
есть содержание, а читатель получает их вместе с текстом, а не ссылкой в никуда.

**В Вики он не публикуется** и адреса страницы в шапке не имеет — отдаётся
файлом или текстом в чат. Остальные четыре документа рано или поздно уезжают
в Вики, этот — нет.

**Команда бизнес-анализа работает по своим правилам** — они лежат не здесь, а в
репозитории `../pbeba` (`docs/playbook.md`, `docs/checklist.md`, `CLAUDE.md`):
у БА нет чекаута кода, и весь порядок работы с агентом строится вокруг базы
знаний, а не вокруг репозитория продукта. Основы из [osnovy.md](osnovy.md)
(доступ, VPN, работа с данными, анти-паттерны) обязательны и для них.

Порядок настройки VPN вынесен в [../vpn/](../vpn/) — он публикуется в раздел Вики про ВПН,
а не сюда. Основы на него ссылаются.

**Правила работы с гитом — в основах, п. 4.7.** Они одинаковы для всех проектов:
локально агент работает свободно, наружу (пуш, PR, мердж) отправляет только человек,
разрушительное запрещено. Документ команды описывает лишь то, что специфично для
её репозитория, — защищённые ветки, сабмодули, брендовые сборки.

**Статус смешанный.** Раздел «Ядро» в основах и правила по работе с данными
обязательны. Остальное — приёмы и рекомендации: спорить с ними можно и нужно
предметно.

**Источник истины по коду и внутреннему процессу проекта — `CLAUDE.md` в корне
его репозитория.** Документы команд на него ссылаются, а не пересказывают:
разошлись — прав `CLAUDE.md`.

команд потом переносим в Вики, [wiki.md](wiki.md) остаётся только здесь.
