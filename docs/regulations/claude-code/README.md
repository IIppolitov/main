Пятым идёт [Яндекс Вики через ИИ-агента](wiki.md) — он не про команду, а про
инструмент, и нужен не только разработке: доступ к API, сценарии чтения и
публикации, грабли, режим работы без чекаута. **Этот документ в Вики не
публикуется** и отдаётся файлом или текстом в чат: тексты скриптов лежат
внутри него, поэтому он работает и у того, у кого нет ни Claude Code, ни
репозитория.

**Команда бизнес-анализа работает по своим правилам** — они живут в рабочем
пространстве бизнес-анализа, а не здесь: у БА нет чекаута кода, и весь порядок
работы с агентом строится вокруг базы знаний, а не вокруг репозитория продукта.
Основы (доступ, VPN, работа с данными, анти-паттерны) обязательны и для них.

**Порядок настройки VPN — в разделе [ВПН: доступ к внешним сервисам](../vpn/README.md).**
Основы на него ссылаются.

**Правила работы с гитом — в основах, п. 4.7.** Они одинаковы для всех проектов:
локально агент работает свободно, наружу (пуш, PR, мердж) отправляет только
человек, разрушительное запрещено. Документ команды описывает лишь то, что
специфично для её репозитория, — защищённые ветки, сабмодули, брендовые сборки.

**Статус смешанный.** Раздел «Ядро» в основах и правила по работе с данными
обязательны. Остальное — приёмы и рекомендации: спорить с ними можно и нужно
предметно.

**Источник истины по коду и внутреннему процессу проекта — описание агента в
корне репозитория этого проекта.** Документы команд на него ссылаются, а не
пересказывают: разошлись — прав он.

Все четыре документа — черновики, ответственный директор департамента
информационных технологий.
