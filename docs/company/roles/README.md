# Роли и должностные обязанности

| | |
|---|---|
| **Версия** | 0.1 — каркас |
| **Дата** | 2026-08-12 |
| **Владелец** | Ипполитов Иван, директор департамента информационных технологий |

Цель раздела — по каждой роли зафиксировать обязанности **в двух видах**:

1. **По регламенту** — что роль делает на каждом этапе, со ссылками на конкретные
   пункты. Живёт вместе с процессом, меняется вместе с ним.
2. **Для документации** — связный текст должностных обязанностей без ссылок на
   этапы. Годится для онбординга, трудового договора, ответа на аудит.

Плюс явное **разграничение**: что в роль не входит и к кому идти вместо неё.
Именно эта часть чаще всего и отсутствует, а спорят как раз о ней.

## Роли вне этого жизненного цикла

У них свои процессы и свои очереди:

| Роль | Процесс | Очередь |
|---|---|---|
| Сотрудник техподдержки | [Процесс техподдержки](../../regulations/support-process.md), этапы 1–3 | `SUPPORT`, `SUPPORTDEV` |
| Руководитель техподдержки | Тот же, этап 4 «Разбор беклога» | `SUPPORT*` |
| Дата-инженер | Регламента нет | `ANALYTIC`, `SUPPORTANALYTIC` |
| Специалист по ИБ | Регламента нет | `CYBERSEC` |

## Что видно из матрицы

**Менеджер клиента — сквозная роль.** Участвует в девяти этапах из четырнадцати и отвечает за
шесть. Весь диалог с клиентом идёт через него, он же управляет статусами на
границах. Узкое место процесса: если менеджер клиента недоступен, задача встаёт на этапах
4, 6, 7, 12 и 14.

**Релиз-менеджер держит середину.** Этапы 5, 8, 10 и 13 — координация оценки,
набор спринтов, мониторинг разработки и релиз. Роль исполняется одним человеком
без заместителя.

**Владелец продукта по CRM — исполняющий обязанности директор департамента
информационных технологий.** Роль отвечает за
[этап 2](../../regulations/crm-lifecycle/02-validacija.md) (валидация — фильтр на
входе в процесс) и участвует в наборе спринтов. Постоянного владельца у роли нет.

Вместе с [релиз-менеджером](release-manager.md) это даёт связку, где обе
координирующие роли жизненного цикла держатся на людях без замещения, а одна из
них совмещается с руководством департаментом.

**ИБ в жизненном цикле не участвует.** Ни на одном из 14 этапов нет проверки
безопасности — ни ревью изменений, ни оценки рисков перед релизом. Для
поставщика фармкомпаний, проходящего аудиты заказчиков, это заметный пробел.

**Дата-инженеры тоже вне цикла.** Их работа идёт через `ANALYTIC` и
`SUPPORTANALYTIC` без описанного процесса — при том, что объём сопоставим
с потоком разработки.
