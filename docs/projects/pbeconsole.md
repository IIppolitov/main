## Назначение

Учёт того, что мы поставляем клиентам. Сущность `Client` = фармкомпания-заказчик;
продукт для неё состоит из двух частей — **Application** ([pbeapp](pbeapp.md)) и
**Admin** ([pbeadmin](pbeadmin.md)). Релизы (`ApplicationRelease`) ведутся по
одному на клиента.

Это единственная из трёх систем, где сходится картина «какому клиенту что и
когда поставлено» — то есть основной источник управленческой отчётности.

## Стек

| Слой | Технологии |
|---|---|
| Backend | PHP 8.2, Laravel 13 |
| БД (прод) | MSSQL (`sqlsrv`), доменные схемы, паттерн «Fields» |
| БД (тесты) | SQLite `:memory:` |
| UI | Tailwind CSS 4 + Vite, Blade, собственная дизайн-система (не Bootstrap/AdminLTE) |
| Интерактив | Alpine.js, Tom Select, ApexCharts (опт-ин) |
| Тесты | PHPUnit 12, Pint |
| Auth | Кастомный `AuthController` (логин `Login`, хэш `PasswordHash`) |

## Доменные области

| Схема БД | Что ведёт |
|---|---|
| `client` | Клиенты, файлы клиентов, инстансы админки, снапшоты |
| `release` | Релизы приложения: стадии, версии, комментарии, возвраты, задачи трекера |
| `access` | Пользователи, роли, права |
| `integration` | Токены трекера, чаты мессенджеров |
| `monitoring` | Цели алертов, ссылки на wallboard |
| `notification` | Уведомления и сообщения |

## Интеграции

Yandex Tracker (`YandexTrackerService`), почтовые уведомления, мессенджеры,
мониторинг с алертами.

## Управленческая ценность

- Прозрачность релизного цикла по каждому клиенту.
- Данные для отчётности руководству и заказчикам.
- Мониторинг — точка раннего предупреждения по инцидентам.
