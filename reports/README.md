# Отчёты и выгрузки

**Содержимое папки не коммитится.** В git только этот файл — всё остальное
исключено в [`.gitignore`](../.gitignore) правилом `reports/*`.

## Раскладка: папка на день

Всё, что здесь появляется, ложится в папку дня сборки — `reports/ГГГГ-ММ-ДД/`:

```
reports/
  2026-09-03/
    moi-zadachi.md
    moi-zadachi.json
    pismo-reglamenty-na-vychitku.md
    pismo-reglamenty-na-vychitku.rtf
    tracker-update-fields-1450.log
  2026-09-02/
    team-load-ba-qa.md
    ...
```

**Дата — в имени папки, в имени файла её нет.** Одно и то же имя в разных днях
и есть история: `2026-09-02/team-load-ba-qa.md` против
`2026-09-03/team-load-ba-qa.md` — тот же отчёт, разные дни, и сравнивать их
удобно именно так.

Исключение — журналы правок Трекера: за день их бывает несколько, и различает
их время, поэтому в имени остаётся `-ЧЧММ` (`tracker-update-fields-1450.log`).

Повторный запуск в тот же день перезаписывает файл. Это осознанно: снимок за
день нужен один, промежуточные прогоны ценности не имеют.

## Зачем так

Отчёты собираются скриптами из Трекера, Вики и БД. Они:

- **воспроизводятся командой** — хранить результат в git незачем, достаточно знать,
  чем он получен;
- **содержат ФИО, трудозатраты и оценки по людям** — данные внутренние, в истории
  репозитория им не место;
- **устаревают за дни** — закоммиченный отчёт через месяц врёт, но выглядит
  достоверно.

Из последнего и растёт раскладка по дням: папка старше двух недель почти
наверняка мусор, и удалять её можно целиком, не разбирая по файлам.

Если из отчёта родился вывод, который нужно сохранить — он идёт не сюда, а в
[docs/](../docs/): решение — в соответствующий документ, открытый вопрос —
в [docs/backlog.md](../docs/backlog.md). Сюда складываются сами выгрузки.

## Как наполняется

```bash
# отчёт по спринтам: оценка, факт, возвраты, сроки → reports/<день>/
automation/scripts/tracker-project-report.py 926 930 --save
```

Папку дня скрипт заводит сам; имя файла составляет из содержания —
`tracker-projects-926-930.md`. Явный каталог вторым аргументом `--save`
берётся как есть, без раскладки по дням: раз указали руками, раскладывать
не скрипту.

Класть сюда что-то руками тоже можно — в папку сегодняшнего дня; в первой
строке файла указывайте, чем он собран.

## Письма

Черновики писем тоже живут здесь — они внутренние, устаревают сразу после
отправки и в истории репозитория не нужны. Имя: `pismo-<тема>.md` в папке дня.

**Письмо готовится в двух форматах сразу:**

| Файл | Для чего |
|---|---|
| `<день>/pismo-<тема>.md` | вычитка и правка здесь, в репозитории |
| `<день>/pismo-<тема>.rtf` | вставка в Mail обычным Cmd+V — жирный, списки, ссылки на месте |

```bash
# .rtf рядом с .md, он же сразу в буфере обмена
automation/scripts/md2rtf.py reports/2026-09-03/pismo-reglamenty-na-vychitku.md
```

Смысл правила: в письмо, отправленное коллегам, не должна попадать
markdown-разметка — ни `##`, ни `**`, ни `[текст](ссылка)`. Вычищать её руками
перед отправкой не нужно, это делает конвертация.

Отправленное письмо — событие проекта. Сам текст остаётся здесь, а факт
отправки и принятые по нему решения переносятся в
[docs/projects/](../docs/projects/) и [docs/backlog.md](../docs/backlog.md):
через полгода понадобится не письмо, а то, о чём по нему договорились.
